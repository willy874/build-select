# v6 · 這版想幹嘛

<div class="text-sm opacity-70 -mt-2">用 filterable 這個 prop 自己開，不加就跟 v5 一模一樣</div>

::left::

**要解的事**

- 長清單（縣市、使用者、商品）一定要能**打字過濾**
- 原生 `<select>` 給不了，v1~v5 也給不了
- 中文情境還得能打**拼音**才找得快

::right::

**怎麼做**

- ✅ 加一個 `filterable` prop（預設 `false`）
- ✅ 開了以後 trigger 變成**可以打字的 combobox**，打就過濾
- ✅ 拼音模糊比對（`pinyin-pro`）＋ 一般子字串
- ✅ 命中的片段會**高亮**，什麼都沒中就顯示「無結果」
- ✅ 對外相容 v5（不加 `filterable` 行為完全不變）

<div class="pt-2 text-sm opacity-60">
拆分的紅利來了：v5 特地留的「值顯示區」，這版直接換成搜尋 input
</div>

---

# v6 · 跟 v5 差在哪

| 面向 | v5 | v6 |
| --- | --- | --- |
| trigger | 靜態 `<div role=combobox>` | filterable 時換成 `<input role=combobox>` |
| 打字會怎樣 | typeahead 跳項 | filterable 時直接**過濾**清單 |
| 中文搜尋 | ❌ | ✅ 拼音（首字母 / 全拼）+ 子字串 |
| 命中怎麼呈現 | — | **命中片段高亮**，沒中就「無結果」 |
| 對外 API | — | 多一個 `filterable`（預設 false），其他都沒動 |

<div class="pt-3 text-sm opacity-60">
多了一個相依 <code>pinyin-pro</code>；完整差異都寫在 <code>src/packages/v6/CHANGELOG.md</code>
</div>
