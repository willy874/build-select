# 04 · 除了做出來，怎麼變成 Library

元件跑得動，不等於別人裝得起來

---
layout: center
---

# 「能用」跟「能給別人用」差在哪

<div class="text-sm opacity-70 -mt-2">v8 跑得起來，是因為它跑在我自己的 dev server 裡</div>

<div class="max-w-3xl mx-auto pt-5 leading-relaxed">

同一份程式碼，換個身分看就變成兩件事：**我手上有原始碼跟我的建置環境，使用者只拿得到產物。**

差別不是「多打一個 build 指令」，是整包責任移到我這邊來了：

- **編譯**：把元件變成瀏覽器讀得懂的東西，從他家的事，變成我的事
- **相容**：他用哪種模組系統、有沒有 SSR，我得先替他想好
- **邊界**：哪些是我承諾的、哪些是內部實作，得先畫清楚
- **樣式**：CSS 沒有模組邊界，它就是會跟他的專案攪在一起
- **依賴**：我裝的東西，最後都變成他的負擔

</div>

<div class="pt-4 text-center text-sm opacity-60">
打包只是其中一件事，而且是裡面最簡單的那件。
</div>

# 依賴邊界：誰跟著走、誰交給宿主

<div class="text-sm opacity-70 -mt-2">整個 library 架構裡，這一刀要最先砍</div>

::left::

**判斷標準：這東西有沒有「身分」**

- 只要同時存在兩份就會出事的，一律交給宿主提供
- 框架本身、狀態容器、任何有全域註冊表的東西，都算這類
- Vue 是最典型的：`provide` / `inject` 靠模組層級的識別、響應式代理不互通、元件實例對不上

<div class="pt-2 text-sm opacity-70">
重點是——這不是體積問題，是正確性問題。<br />
兩份 Vue 不會報錯給你看，它只會行為很詭異，而且超難查。
</div>

::right::

**純工具可以跟著走，但代價要自己算**

- 這顆 Select 為了中文搜尋用了 `pinyin-pro`
- 它揹著一份拼音字典，安裝體積大概 1 MB，而且字典類的資料幾乎搖不掉
- 一個「打拼音也能搜」的方便功能，讓**所有人**一起付這個成本——包含只想要一顆單選下拉的那個人

<div class="pt-2 text-sm opacity-70">
路其實有幾條：做成可選依賴、把比對函式開放讓使用者自己注入、或拆成獨立入口。<br />
真正要決定的是：<strong>預設要不要幫使用者做主。</strong>
</div>

# 出口設計：開出去的就是承諾

<div class="text-sm opacity-70 -mt-2">出口不是「讓人 import 得到」，是「決定哪些東西以後不能亂改」</div>

<div class="max-w-3xl mx-auto pt-5 leading-relaxed">

- 沒開的路徑，使用者進不去——這條限制其實是在**保護我以後還敢重構**
- 反過來也一樣：只要有人深入 import 到內部檔案而且真的能用，那條路徑就變成**事實上的公開 API**，你以後改它就是破壞性變更，就算你從來沒承諾過

</div>

<div class="max-w-3xl mx-auto pt-4 leading-relaxed">

這顆 Select 實際上是這樣切的：v8 對外只開 `Select` 元件跟四個型別，六個 composables 全部關在裡面。

- **開出去**：使用者可以自己組一顆 Select，但這些東西的參數跟回傳，以後我就不能亂動了
- **不開**：我保留調整空間，代價是彈性只能靠 props 跟 slots 給

</div>

<div class="pt-4 text-center text-sm opacity-60">
沒有標準答案，但要在發佈前決定——不是等別人用了才決定。
</div>

# 產物形態：使用者能不能只拿他要的

<div class="text-sm opacity-70 -mt-2">格式對了，不代表搖得掉</div>

<div class="max-w-3xl mx-auto pt-5 leading-relaxed">

**為什麼不能只出一種格式**

- 消費端不只一種：打包器、直接丟進瀏覽器、Node 環境的 SSR
- ESM 的意義不是「比較新」，它是讓打包器能靜態分析、進而 tree-shaking 的前提

**但格式只是入場券**

- 打成單一 bundle 的時候，內部引用關係被壓平了——他只要一顆 Select，還是可能整包扛走
- 有副作用的檔案（引樣式、全域註冊）打包器不敢刪，你得**主動宣告**哪些檔案沒有副作用
- 保留原始檔案結構輸出，對 tree-shaking 友善；單一 bundle 則是簡單好懂

</div>

<div class="pt-3 text-center text-sm opacity-60">
這輪就停在單一 bundle，而且對外入口只開到 v1——夠用，但還不到能給人裝的程度。
</div>

# 樣式：元件庫最難交出去的一塊

<div class="text-sm opacity-70 -mt-2">JS 有模組邊界，CSS 沒有——它注定要跟使用者的專案共用同一個全域空間</div>

::left::

**要怎麼交出去**

- **獨立 CSS 檔**：使用者得自己引一行，但他能控制載入順序，也能選擇不要
- **打進 JS 自動生效**：省事，代價是難覆寫，SSR 也容易出事

**可覆寫性是設計出來的，不會自己長出來**

- 這顆 Select 八個子元件全部 `scoped`，樣式不外洩很好——但這也代表使用者的覆寫進不來，只能靠權重硬壓

::right::

**哪些東西一被覆寫就變成 API**

- class 命名（`bs-select__*`）只要有人拿去覆寫，它就跟 props 一樣是公開介面，改名就是破壞性變更
- DOM 巢狀結構也一樣——人家的選擇器就是照著它寫的

**比較可控的做法**

- 把可以調的部分收斂成 CSS 變數，當成一個明確、有限、可以承諾的樣式介面
- 主題跟深色模式是變數層的事，不該讓每個子元件各自去判斷

<!--
講者備忘：scoped 是「防止外洩」，不是「提供客製化」。
這兩件事常被混為一談，但使用者最後一定會想改樣式。
-->

# 版本與契約：你承諾的比你以為的多

<div class="text-sm opacity-70 -mt-2">版本號是拿來溝通的，不是拿來把數字排整齊的</div>

<div class="max-w-2xl mx-auto pt-6">

**「公開 API」到底包含什麼**

- props / events / slots —— 這個大家都知道
- **型別**：型別檔是機器讀得懂的契約，收窄它會讓使用者編譯不過
- **DOM 結構跟 class 名**：人家拿它來覆寫樣式
- **行為細節**：預設值、事件在什麼時候、用什麼順序丟出來

<div class="pt-2 text-sm opacity-70">
只要別人的程式碼會因為你的改動而壞掉，那就是破壞性變更——跟你有沒有寫在文件上完全無關。
</div>

</div>

# 這輪做到哪、還差什麼

<div class="text-sm opacity-70 -mt-2">誠實版：這個 repo 現在就長這樣</div>

::left::

**已經有的**

- 產物三種：ESM、UMD、獨立樣式檔
- 型別檔跟著一起發
- 出口跟發佈範圍有講清楚
- Vue 沒打進產物，用宿主那一份
- Storybook 當元件文件
- 每一版都有自己的 `CHANGELOG.md`

::right::

**還沒做的**

- 對外入口只開到 v1，v2 ~ v8 還沒出口
- Vue 還掛在一般依賴，應該宣告成 peer
- `pinyin-pro` 無條件跟著走，還沒做成可選
- 樣式只有 scoped，沒有對外的 CSS 變數介面
- 沒有測試也沒有 CI，而且根本還沒真的發佈過

<div class="pt-3 text-xs opacity-60">
「做成 library」不是打包完就結束——後面這排，才是別人敢不敢信你的地方。
</div>
